Pemrograman

Dari logika dasar sampai arsitektur kode yang dipakai developer profesional. Klik tiap topik untuk membuka penjelasannya.

4 topik Level: Semua

Algoritma adalah urutan instruksi yang jelas dan terbatas untuk menyelesaikan masalah. Pseudocode menuliskan logika itu memakai campuran bahasa manusia dan sintaks ringan.

  • Input, Proses, Output — struktur dasar setiap algoritma.
  • Flowchart — visualisasi algoritma; oval = mulai/selesai, jajar genjang = input, persegi = proses, wajik = keputusan.
  • Contoh pseudocode — IF nilai ≥ 75 THEN lulus ELSE ulang.
  • Ciri algoritma baik — jelas, efektif, efisien, dan memiliki batas langkah.

Tips

Tulis pseudocode dulu sebelum mengetik kode — sebagian besar error muncul karena langsung coding tanpa rencana.

Pilihan struktur data menentukan performa program saat data membesar. Struktur yang salah artinya program ikut melambat.

  • Array — daftar data sejenis berindeks; akses cepat O(1), sisip dan hapus lambat.
  • Stack (LIFO) — tumpukan, terakhir masuk pertama keluar; cocok untuk fitur undo.
  • Queue (FIFO) — antrian, pertama masuk pertama keluar; untuk antrean proses atau print.
  • Linked List — node saling menunjuk; sisip cepat tapi pencarian berurutan.
  • Tree & Graph — hierarki dan relasi kompleks; dipakai file system, GPS, dan media sosial.
  • Hash Map — penyimpanan kunci-nilai dengan pencarian instan O(1).

Trik

Mau pencarian cepat? Hash Map. Mau antrian FIFO? Queue. Pilih sesuai kebutuhan, bukan yang paling keren.

Paradigma adalah gaya dalam menulis program. OOP (Object-Oriented Programming) adalah yang paling populer karena mendekati cara pikir dunia nyata.

  • Prosedural — instruksi berurutan; contoh C dan Pascal.
  • Fungsional — fungsi murni tanpa efek samping; contoh Haskell, sering dipakai dalam Python.
  • Encapsulation — sembunyikan detail internal (private).
  • Inheritance — class anak mewarisi sifat class induk.
  • Polymorphism — satu antarmuka, banyak bentuk perilaku.
  • Abstraction — tampilkan esensi, sembunyikan kompleksitas.

Mnemonic

Ingat 4 pilar OOP sebagai CEPA — Capsule, Extend, Poly, Abstract.

Design pattern adalah "resep" kode yang sudah terbukti, bukan library — tinggal diadaptasi ke masalah nyata yang cocok.

  • Creational — mengatur pembuatan objek; contoh Singleton, Factory, Builder.
  • Structural — merangkai class dan objek; contoh Adapter, Facade, Proxy.
  • Behavioral — komunikasi antar-objek; contoh Observer, Strategy, Command.
  • Manfaatnya — kode lebih mudah dibaca, dipelihara, dan tim punya bahasa bersama.

Peringatan

Jangan paksakan pattern — gunakan hanya saat masalahnya benar-benar cocok, bukan sekadar biar terlihat pro.
